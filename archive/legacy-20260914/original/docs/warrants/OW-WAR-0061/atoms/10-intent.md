# Intent

Give Phase 1 an exit that can be discharged.

## Where Phase 1 stood

§98 gives Phase 1 — the file-native WAR compiler — ten deliverables and one
Exit: "OpenWarrant development uses WARs." Seventeen Warrants name the
phase; none carries the `exit` slug, so the corpus projection reports the
Objective as "not derivable — no member carries the `exit` slug". The
phase's work is the most complete in the corpus and it can never read
achieved, because nothing was written that could discharge it.

## What this delivers

A Warrant whose obligations are the Exit sentence made measurable, and a
short report that records the measurement:

- the ten Phase 1 deliverables each exist as a command or module and are
  exercised by the gate that runs on every push;
- the repository's own work is carried as Warrants — every one compiles,
  is drift-checked in CI, and carries the owner's authorization;
- at least one Warrant has gone end to end through §56 with a real gate
  receipt, so "uses WARs" means the closing seam too, not only the drafting
  one;
- how much of the commit history names a Warrant, measured and written
  down rather than assumed.

When this Warrant resolves satisfied, the Objective reads `Recorded`. Until
then it reads blocked by name, which is the true state.

## What this does not do

It does not enforce the fourth point going forward. A gate step that
inspects commit subjects needs history that CI's shallow checkout does not
fetch; that is a separate Warrant, and the measured number is recorded
here so the next reader knows where it started.
