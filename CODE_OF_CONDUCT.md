# Code of Conduct

## The short version

Be straight with people, and be accurate about the work.

## Expected behaviour

- Discuss the work, not the person doing it.
- Take disagreement about technical claims as normal and settle it with
  evidence. "I ran it and here is the output" ends an argument; "obviously" does
  not.
- Say what you actually measured, and say what you did not. Overstating a result
  wastes everyone's time downstream, and this project is specifically about not
  doing that.
- Accept correction without treating it as an attack, and offer correction
  without making it one.
- Assume the other person is trying to get it right.

## Unacceptable behaviour

- Harassment, personal attacks, or demeaning comments — including about someone's
  identity, background, or experience level.
- Sustained disruption: relitigating settled decisions without new evidence,
  or derailing threads.
- Publishing someone's private information.
- Deliberately misrepresenting a measurement, a test result, or someone else's
  position.

## Scope

Applies in this repository — issues, pull requests, discussions, commit
messages, code comments — and in any space where you are representing the
project.

## Enforcement

Report to the maintainer at **briankhanglam@gmail.com**. Reports are handled
privately.

This is a small project with one maintainer. The realistic range of responses is
a request to change behaviour, removal of a comment, or a block. There is no
committee and no appeals process, so the standard applied will be whether the
behaviour makes the project worse to work on.

The maintainer is bound by this document too. If the problem is the maintainer's
conduct, saying so publicly in an issue is legitimate.
