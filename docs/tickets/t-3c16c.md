# OpenWarrant lean programme

The owner's single plan for OpenWarrant, 2026-11-05. It continues `docs/design/alpha6-implementation.md`, `OW-ADR-alpha6-unified-work-8956e` and `t-8956e`, which stay as written, and it records where this plan narrows them. This is a Ticket: no trigger and no signature. It authorizes nothing and does not replace the signed roadmap.

## The lean model (owner, 2026-11-05)

One item, one format, three levels. The level is derived from the fields and never stored.

| Level | What makes it one | What done means |
|---|---|---|
| **Ticket** (default) | Nothing extra | The agent says it's done |
| **Warrant** | A trigger for completion, such as a test or gate | The trigger passed |
| **Order** | A required human signature | The trigger passed, if any, and a human signed at the end (the default) |

- Six CLI commands: `init`, `create`, `start`, `done`, `status`, `check`. `war` alone is the TUI. `--interactive` gives humans an interactive mode on all six. `war sign` stays for humans, outside the agent loop.
- Every document in the format is parsed by OpenWarrant.
- Ordinary coding needs nothing. A test on a ticket is cheap and always optional. Enforcement stays opt-in; a default-on gate was proposed by the feedback and then withdrawn.
- Existing directory Warrants stay readable as a stored encoding. Signed records are never rewritten.

## Rules for all work

- Unknown is shown as UNKNOWN, never estimated into a real-looking number.
- The TUI holds no signing keys and computes no state of its own.
- Every action a tool offers is a real, tested command.
- Agents' token cost is a product measure: terse by default, details behind `--verbose`.
- PRs need green fast CI; the full gate runs before any release or downstream pin.
- Normative FORMAT and SAS text changes wait for a signing sitting. They never interrupt work.

## Permissions (owner, 2026-11-06)

`paths:`, `x.tools:` and `x.commands:` are optional at every level and never change an item's level: the level says how work ends, permissions say how it runs. None declared means no limit. `x.tools` and `x.commands` are critical extensions (FORMAT 7.3), so `war create` lists them in `requires:`. A signing sitting can promote them to undotted keys.

| Level | What a declaration means |
|---|---|
| Ticket | Cooperative: `war start` applies it, and anyone can edit it |
| Warrant | Also, a widening after work starts is flagged at `war done` (needs W3) |
| Order | Widening takes a new signed revision (needs W3) |

## W2: context compiler that serves real documents (top priority after W0)

The feedback holds up. `war context` refuses `docs/TICKETS.md` and FORMAT-1.0 at the default budget, sections of ordinary documents can't be selected, topics and directories are `target-unknown`, and no response reports savings. A refused agent reads the whole file, the worst outcome for tokens.

1. **Long documents defined in the format.** Add document units and a generated index to the format, so any long Markdown document has stable section ids. Reuse §3.4 units and `doc_index.rs`; keep ids stable across heading edits with an optional explicit id. Consumers such as WMD's 279 units in #70 then work directly.
2. **Unit selection:** `war context 'COMBAT.md#friendly-fire'`, extending `md:` beyond instruction files (`instructions.rs`, `context/mod.rs` `resolve`).
3. **Degrade by default.** Over budget returns the unit index plus the most relevant units that fit, with every cut declared (§12.2). `--strict` refuses; `--full` returns everything anyway. Until the FORMAT rule (line 778) and corpus case 302 are amended at a sitting, this ships as a separate packet kind so the normative path stays conformant, following `oh.war/task-context/v1`.
4. **Topic queries:** `war context "friendly fire"` returns ranked units within budget. Deterministic, local and model-free: a term index over units, cached under the git common directory's `openwarrant/cache`. `target-unknown` falls back to it.
5. **Code paths:** `war context crates/.../world.rs` returns governing units. Units declare `paths:`; directories match; wide matches are ranked and fitted instead of rooting all 76 Warrants that name `lib.rs`.
6. **Token accounting:** every packet reports the bytes of its sources against the bytes returned, in the envelope and in telemetry.
7. **One record model:** tickets, Warrants and Orders resolve identically (from W1.1).

## W3: live updates to running agents

Today nobody is told. `war plan impact` ignores claims, nothing reads a packet's `source_manifest`, and a worktree can't see an amendment made on main.

1. **Record what each agent was given.** `war start` keeps the `task-context` source manifest beside its claim.
2. **Detect changes** at every `war` write, in the stop hook's `check --changed`, and in an optional git post-commit/post-merge hook, so plain edits to documents and plans count too.
3. **Find who's affected.** Extend `impact.rs` to include claims: a claim is affected when a changed unit reached it through relations, its manifest, or overlapping declared paths. Others hear nothing.
4. **Post a notice** under `<git common dir>/openwarrant/notices`, which every worktree sees, with `refs/openwarrant/notices` for other clones (the claims pattern in `ticket/remote.rs`). Each notice carries one required line: what changed and what to do.
5. **Deliver in tiers:** the next `war` call prints one deduplicated line; `war start` prints only the changed units and records them as seen. Faster where available: Claude hooks, Herdr `agent.prompt`, the TUI feed. A harness with none of these still gets it on its next call.
6. **Enforce at done.**
   - Ticket: warns and closes.
   - Warrant: refuses until the change has been seen, then runs the trigger against the new state.
   - Order: the same. A change to what's being signed takes a new signed revision. Agents may amend Tickets and Warrants; amending a signed Order takes a human.

Delivery and passing triggers can be proven; understanding can't. A spec change that matters should carry a test. Two agents touching the same code stays a merge matter: overlap warnings, plus the trigger re-run on merged state.
