# Protected BLUT host and SDK integration

The SDK holds independently captured key, plan, producer and complete job snapshots through native verification. `runtime assess --native-store` selects these inputs from authenticated operator-owned host policy. BLUT requires explicit `oh.war/runtime-native-config/v2-draft.1`, a positive aggregate budget at most 2 GiB, and an independently configured canonical BLAKE3 catalog digest. Existing v1 Katana policy retains its 128 MiB aggregate ceiling. The public single-input primitive supports at most 1 GiB for native producer identity; each caller still supplies its own positive limit.

The adapter invokes only the activated verifier, with a bounded sealed-input manifest. It does not execute the retained producer, activate authority or substitute ordinary paths for missing sealed inputs. Existing BLUT v1 argument order and no-follow transport remain intact. SHA-256 capture identity and native BLAKE3 receipt/catalog identities remain distinct.

A Linux namespace fixture runs separate operator and executor UIDs over an emitted prototype Dispatch. The selected current-source BLUT CPU fixture creates a signed native receipt with a public test key. Protected CLI assessment matches it without granting assurance. Paired controls reject wrong catalog, absent or insufficient budget, wrong key digest and wrong source mode. Legacy BLUT host policy, required confinement and required accounting remain UNKNOWN. Changing protected policy after loading invalidates the held verifier before launch. Default and actual Katana namespace checks cover compatibility.

Failures remain in the evidence: the pre-implementation case rejected unsupported host schema; an initial test-control placement failed compilation; the first broader runtime run failed because an ordinary-process fixture depended on the original argument order. The order was restored without changing the fixture or weakening the control. Final results and exact hashes are in `observation.json` and retained compressed logs.

This is implementation evidence from a scripted CPU fixture. It is not production key custody, hardware human presence, metered cost, confinement, an atomic revocation fence, independent qualification or Warrant completion. External BLUT PR103 and PR104 still require genuine contributor agreement. Study participants are not available. Historical observations, signatures and dispositions are unchanged.

Record/projection integrity: 2,028 passes, 625 warnings, zero errors and zero unknowns. This check executes no repository gate. The candidate is submitted to the full main-branch CI gate separately.
