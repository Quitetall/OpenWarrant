The native BLUT implementation is pushed in [draft PR104](https://github.com/Quitetall/blut/pull/104), dependent on PR103. It implements shared OW-WAR-0149 prototype work, not another project's acceptance, contributor agreement or assurance. Both PRs have a failing CLA check; neither has been merged or waived here.

`openwarrant verify --sealed-inputs` selects `blut/openwarrant-verification/v2`. The bounded strict manifest identifies independently captured public key, plan, producer and complete job file descriptors with original source modes. The Linux reader requires canonical immediate-parent descriptors, regular non-executable objects and all kernel immutability seals. Signature, binding, plan/catalog, producer, original modes, full job file table and lifecycle must match. Native receipt schema/hash domains and ordinary v1 no-follow transport stay unchanged; mixing transport modes refuses. No plan is rerun.

The public native-library test first failed on missing API. An initial implementation compilation failed on optional parent PID handling; that was corrected to report unavailable parent explicitly. The first Clippy run found an empty-string comparison and refused warnings; the final lint run passed. All 12 final native receipt cases passed on Rust 1.99.0. The one default-ignored child helper is explicitly selected and checked by the new parent test. The child validated actual CPU job evidence after original-job deletion, and refused mutable descriptor, changed job bytes, changed source modes, duplicate path and v1 descriptor substitution. Exact source/binary hashes and original failures are retained here.

The actual built native example CLI also passed with a CPU `connector_object` fixture, using a deliberately public test key and synthetic transport-only binding. It validated frozen inputs after moving the original job, refused mutable key and mixed options, and awarded no assurance. The stage declares an object reference; it does not prove that object is available. Original receipt, producer data, plan, key, catalog/binding inputs and full original job remain in the runtime evidence under `~/Projects/OpenWarrant/docs/runtime-evidence/native-kf-recovery-20261010/blut-sealed-cli-fixture/`. Descriptor paths are inert historical references after their handles close; replay requires explicitly recapturing retained bytes. No retained producer is executed by import or replay.

OpenWarrant's protected host/SDK/CLI wiring, exact dispatch-bound two-account BLUT integration, independent expected catalog policy, production key custody, spend/confinement observations and independent qualification remain. This proof is native transport acceptance, not completed OW-WAR-0149 or a fulfilled runtime requirement for a real Warrant.
