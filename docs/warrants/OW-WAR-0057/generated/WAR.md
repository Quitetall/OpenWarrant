# Intent

A page a person opens. OW-WAR-0055 made the corpus projection real —
`CORPUS_STATUS.json` is the contract an agent reads and `CORPUS_STATUS.md` is
the same thing for a reader with a Markdown viewer. Neither is a page.

## What this delivers

`CORPUS_STATUS.html`: one file, generated by `war compile` next to the JSON,
committed, and drift-checked like every other generated view. It embeds the
canonical JSON verbatim and renders it in the browser. No framework, no fetch,
no CDN — it opens from disk, from a GitHub Pages checkout, or from any static
host, and it works with the network off.

## What this deliberately is not

- Not a server. `Cargo.toml` records the refusal of an async runtime, and a
  page that fetched live state would be a second surface that could disagree
  with the committed projection. The page writes nothing and reads nothing
  but itself.
- Not a second source of truth. The JSON is the contract (§77.3: consumers
  take generated schemas; they do not reimplement WAR semantics). A Huly sync
  or a herdr pane reads the same JSON this page does. None is built here.
- Not a percentage. The page inherits the projection's rule: every number is
  a rung count or a histogram of names, and the strictest rung is the
  headline. Today the headline reads `0 satisfied`, on purpose.

## The one visible thing that matters

The provenance banner. Every state on the page is derived from the records'
shape; nothing is recorded. The banner says so at the top, before any number,
because a reader who scrolls past it will read `draft` as a verdict rather
than as the honest absence of a journal.

# Work Order

## Deliverables

1. `render_html(status, canonical_json) -> String` in the compiler crate: a
   single HTML file with the §17.1 generated banner as a comment, the
   canonical JSON inlined in a `<script type="application/json">` element
   (`</` escaped so no content can close it), and an inline renderer that
   builds the page from that element. Deterministic: the bytes are a fixed
   template plus the canonical JSON.
2. Sections, in order: the provenance banner and caveats; Release with the
   requirement ladder; Objectives with exit Warrant, achievement and ladder;
   Next actionable; what blocks resolution, by requirement name; Requirements,
   unaddressed first; Warrants; Not reported here.
3. Theme-aware: light tokens on `:root`, dark under `prefers-color-scheme`.
   Wide tables scroll in their own container; the body never scrolls
   horizontally.
4. `CORPUS_STATUS.html` under `docs/warrants/generated/`, emitted on
   full-corpus `war compile` beside the JSON and Markdown, drift-checked by
   `war check --generated` under the existing `corpus-status` rule.
5. A link from the page to the JSON it was built from, and a line naming the
   Markdown twin.
