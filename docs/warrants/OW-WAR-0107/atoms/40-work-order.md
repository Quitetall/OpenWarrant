# Work Order

1. Define opt-in workflow verification configuration and request/result contracts
   bound to exact Warrant source, execution policy, candidate commit and check set.
   Preserve current prototype behavior and all existing immutable records.
2. Dispatch a configured verifier with separate context and isolated Git workspace.
   Bind actual configured performer/verifier identities and required harness
   capabilities. Refuse self-verification, mutable candidate, unknown writer,
   missing protections, unsupported fields and unknown-cost mandatory caps.
3. Retain check observations, bounded findings and verdicts without granting
   qualification. PASS, FAIL and UNKNOWN stay distinct. Recheck candidate and
   protected expectations before accepting the verifier result.
4. For repairable findings, run bounded repair under the same Warrant and existing
   writer controls; independently verify the resulting exact revision again.
   Preserve prior findings/results. User-selected repair count wins; fallback is
   three. Recovery and rebuttal counts do not silently consume or reset repair
   budgets. Time/spend limits apply across the loop.
5. Accept evidence-backed performer rebuttals for independent recheck. Performer
   cannot dismiss findings or clear its own gate. Unresolved disagreement routes
   to authorized human; absent responder remains visible waiting. Stale answers or
   changed candidate require new verification rather than reusing old PASS.
6. Expose configuration/readiness, bounded actions, pending findings, repair/recheck
   progress and escalation through local API/browser and deterministic reports.
   Verification is optional for unmarked prototype completion. No agent output
   awards the assurance mark or authorizes merge/deployment.
7. Test public HTTP/process/Git seams and browser flow: successful independent
   check, self-verifier refusal, stale result, changed mandatory checks, failed and
   unknown verification, bounded repair/exhaustion, rebuttal/recheck/escalation,
   restart/idempotency and hard cost-cap refusal. Retain exact full-gate evidence.

Autonomy: prompt-authorized unverified implementation, no paid calls. Synthetic
processes demonstrate contracts only, not model quality or external sandbox proof.
Preserve signed records and delivery pins. Roll back code through Git while keeping
actual observations and authority history.
